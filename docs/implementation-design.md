# 素材制作网站实现方案

更新日期：2026-10-29。本文是开发设计基线；实际实现和运行验证范围见 verification.md，接口细节见 api-contract.md。

## 1. 目标与范围

交付可独立运行、可通过容器验收的素材制作网站。用户注册登录后浏览模板、上传图片、提交任务，在后台处理期间继续使用网站，查看个人历史和结果。无需真实 AI 服务，使用耗时可调、可指定阶段失败的模拟生成器。

重点满足 R-01 至 R-14：Java 多步骤异步处理、MySQL 持久化、前端多任务状态管理、用户隔离、测试与容器交付。

用户已选择方案 A：同源 API、Java Session 认证、Java 有界线程池、MySQL。已明确需要用户名／密码注册登录。修改密码及账户弹窗按本方案规划。

附件作为深色主题、圆角卡片和制作页左右布局参考。账户截图纳入账户功能参考；账单、订阅、积分、第三方登录、任务删除和重试不纳入范围。

## 2. 技术栈与职责

- 前端：Next.js App Router、React、TypeScript、TanStack Query、CSS。
- 后端：Java 21、Spring Boot 3、Spring Security、MyBatis、Flyway。
- 数据库：MySQL 8.4。
- 文件：后端本地文件系统，容器数据卷持久化。
- 执行：Java 有界线程池；不引入 Redis、消息队列、SSE 或 WebSocket。
- 具体框架补丁版本须在实现前核对兼容性并锁定，最终在 README、依赖文件及锁文件中记录。

浏览器通过同源 `/api` 访问 Java；开发和容器环境通过 Next.js rewrite 转发。Next.js 负责页面和转发，不执行制作业务或替代 Java 持久化。数据库与文件存取由 Java 管理。

## 3. 页面

| 页面 | 功能 |
| --- | --- |
| 注册／登录 | 用户名、密码、确认密码、字段校验、请求反馈 |
| 模板列表 | 分类筛选、封面、标题、图片数量要求 |
| 模板详情／制作 | 左侧模板与上传位，右侧当前模板个人任务 |
| 全部历史 | 分页展示任务、时间、阶段、结果或失败原因 |
| 账户弹窗 | 用户名、注册时间、修改密码、退出登录 |

制作页桌面采用双栏，小屏上下排列。提供加载、空数据、不存在、请求失败状态；保留键盘焦点，为上传位和图标按钮提供语义标签。结果支持图片预览。

登录成功返回原访问页面。账户不采集邮箱，不展示虚构邮箱，不实现邮件找回。修改密码需验证当前密码，完成后使该用户现有会话失效并重新登录。

## 4. 认证与权限

- 用户名唯一，密码使用 BCrypt 哈希，不保存或返回明文。
- Java 使用 Spring Security 和服务端 Session；登录更新 Session ID，退出销毁 Session。
- Cookie 为 HttpOnly、SameSite=Lax，HTTPS 环境启用 Secure。
- 保留 CSRF 防护，写请求携带 CSRF Token。
- 素材、任务、结果均按当前用户检查归属，不接受客户端指定业务用户 ID。
- 切换用户时取消旧请求、清除缓存，避免旧响应覆盖新用户数据。
- 单实例内存 Session，重启后重新登录；用户和历史记录保存在 MySQL。

## 5. 数据模型

| 表 | 主要字段 |
| --- | --- |
| users | ID、用户名、密码哈希、创建时间 |
| template_categories | ID、名称、排序 |
| templates | ID、分类、标题、描述、封面、数量、类型和大小限制 |
| assets | ID、用户、路径、实际类型、大小、尺寸、上传时间 |
| creation_tasks | ID、用户、模板、标题快照、状态、阶段、失败原因、结果路径、模拟配置快照、时间 |
| task_assets | 任务、素材、槽位顺序 |
| task_step_runs | 任务、阶段、状态、开始／结束时间、错误 |

Flyway 管理数据库结构与种子数据。演示模板应覆盖不同分类及一张、两张等不同数量要求。封面、素材和预置结果随项目提供，记录来源，不依赖付费或内部资源。时间按 UTC 存储，接口返回 ISO 8601，前端按本地时区展示。

## 6. 上传

上传位独立经历空、上传中、已上传、上传失败状态，支持预览、替换、移除及重试。前端检查数量、类型、大小；Java 检查实际可解码类型、大小、尺寸上限、归属及文件存在性。

文件采用服务端随机名称，原始文件名不得参与存储路径拼接。临时浏览器 URL 只用于预览，提交任务使用 Java 返回的素材 ID。未上传完成或提交中禁用提交；受理成功立即结束提交状态，保留素材以支持连续创建。

## 7. 多步骤异步执行

整体状态：`QUEUED → RUNNING → SUCCEEDED / FAILED`。

阶段：`MATERIAL_CHECK → MOCK_GENERATION → RESULT_PACKAGING`。

1. 接口校验模板、图片数量、顺序、重复 ID、素材归属与模拟参数。
2. 短事务创建任务和素材关联，保存模拟配置快照，状态为 QUEUED。
3. 事务提交后交给线程池，接口返回 202 及任务 ID，不等待完成。
4. Worker 通过条件更新领取任务，避免重复执行。
5. 每阶段开始和结束分别持久化，使边界可查询；等待和文件操作不占长事务。
6. 指定阶段失败时记录阶段、错误码、可理解原因与结束时间，停止后续步骤。
7. 整理结果先写临时文件再移动至正式位置，最后持久化结果并置为 SUCCEEDED。

默认两个线程和有界队列，参数可配置。调度被拒绝时将记录置为 FAILED，保存队列已满原因，不遗留永久等待任务。终态不可回退；查询只读，不驱动执行。

服务重启不续跑任务；启动时将遗留 QUEUED/RUNNING 任务标为失败，原因明确为服务重启导致中断。单实例部署，不支持多实例争抢和集群恢复。

## 8. 模拟生成器

任务配置包括每阶段毫秒延迟和可空的 failAtStage。默认延迟建议 1000／6000／1000ms。开发页面提供折叠控制区，Java 校验范围并保存快照，生产环境关闭控制入口。

指定阶段延迟结束后可重复触发失败；无随机失败。成功时复制随项目提供的模板结果到任务专属目录，并标注模拟结果。无需真实图片合成。

## 9. 前端异步管理

- 区分本地上传／提交状态、后台任务状态、查询请求状态。
- 任务按 ID 更新；Query Key 包含用户身份，列表还包含模板及分页条件。
- 登录后查询 active 接口，存在未完成任务时约每两秒刷新。
- 活跃列表中消失的旧任务单独查询终态，更新详情及历史缓存。
- 无活跃任务时停止定时查询；创建成功、重新聚焦或网络恢复时重新核对。
- 查询异常保留已有信息，显示暂时无法更新及恢复按钮，绝不将任务标为失败。
- 刷新加载用户、历史及活跃任务；页面离开取消相关请求和订阅。
- 退出取消请求并清理缓存，使用 AbortSignal 和身份维度缓存防止串扰。

接口详情见 [前后端接口契约](api-contract.md)。

## 10. 测试与 CI

Java：步骤顺序、阶段失败中断、快速受理、多任务配置隔离、查询不推进、终态不回退、用户隔离、事务后调度、队列拒绝。流水线单元测试无需真实等待；MySQL 集成测试使用 Compose／CI service 提供的真实 MySQL 容器，避免测试容器内再启动容器。

前端：多任务独立更新、查询异常与执行失败区分、终态和空队列停止轮询、切换用户取消旧响应、上传和提交防重复。可用 Vitest、React Testing Library、MSW。

GitHub Actions 在 push 和 pull_request 执行前端 lint、类型检查、测试、构建，以及 Java 测试与构建。安装、测试和运行提供容器入口，验收不依赖宿主机执行项目脚本。

## 12. 交付、部署与限制

Compose 启动前端、Java、MySQL，配置健康检查、数据库和文件持久卷。README 给出 docker compose up --build、配置、初始化、构建测试命令、接口、演示流程、身份方案、完成状态、实际投入和来源说明。

部署先备份数据库及文件卷，再构建镜像、迁移、启动及健康检查；回滚用上一版本镜像，非兼容数据库迁移须恢复配套备份。

不实现真实 AI、支付、复杂模板后台、邮箱找回、第三方登录、集群、断点续跑、自动重试、任务受理幂等。未引用素材清理作为已知限制记录。不得把源码实现等同于运行验证，README 分别说明。
